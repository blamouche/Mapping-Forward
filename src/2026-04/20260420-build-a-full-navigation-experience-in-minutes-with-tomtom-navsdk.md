# Build a full navigation experience in minutes with TomTom NavSDK
**Source**: https://www.webwire.com/ViewPressRel.asp?aId=353623
**Date**: 2026-04-20
**Author**: Unknown
**Keywords**: TomTom, NavSDK, Android, developer tools, software-defined vehicles

## Elevator pitch
TomTom positions NavSDK v2 as a faster path from developer onboarding to production-grade in-app navigation, turning maps, routing, traffic and EV support into a more accessible software stack.

## Takeaways
- TomTom says NavSDK v2 combines map rendering, search, routing, navigation and traffic in one Android-focused SDK.
- The company is emphasizing self-service evaluation through its developer portal rather than sales-led onboarding.
- New Kotlin APIs and Jetpack Compose components are presented as the main tools for rapid integration.
- TomTom frames faster integration as strategically important for software-defined vehicles and in-vehicle experiences.
- Orbis Maps is positioned as the data foundation behind the SDK’s map quality and connected services.

## Synthesis
This TomTom press release presents NavSDK v2 as an effort to reduce the complexity historically associated with embedding navigation into Android and automotive applications. The central claim is not about a new consumer feature but about developer workflow. TomTom argues that teams building connected mobility products, especially in automotive, lose time when they have to assemble mapping, routing, traffic and guidance from loosely connected components. NavSDK v2 is framed as a response to that friction by packaging those capabilities into a single coherent toolkit.

A major theme is onboarding speed. TomTom says developers can now self-evaluate the SDK directly from the TomTom Developer Portal instead of first going through sales conversations and longer setup cycles. That matters because it lowers the threshold for experimentation. For platform teams, startups, or OEM innovation groups, reducing commercial and technical friction can make the difference between testing a navigation concept quickly and abandoning it early. TomTom’s language suggests it sees this as a competitive differentiator in a market where speed to prototype increasingly matters.

The article also emphasizes the practical development stack. NavSDK v2 includes Kotlin APIs and Jetpack Compose components, which should make it easier for Android teams to build map-based user interfaces natively rather than bolting together separate libraries. TomTom highlights that a complete navigation application, including turn-by-turn guidance and EV support, can be assembled in minutes. Even if that promise reflects an idealized demo environment, it signals a deliberate move toward productizing navigation as a more modular software capability.

TomTom links this release to the broader shift toward software-defined vehicles. In that framing, navigation is no longer a static feature but a core software layer that needs to evolve quickly, integrate cleanly, and remain maintainable over time. The company argues that map and navigation systems underpin infotainment, driver assistance and future automation use cases, so reducing implementation complexity is not only a developer convenience but an automotive business issue.

Finally, the release positions Orbis Maps as the data backbone of this SDK strategy. TomTom describes Orbis as a fresh, collaborative mapping foundation built on open standards, with validated data and online services layered on top. Overall, the message is clear: TomTom wants developers and carmakers to see navigation less as a difficult integration project and more as a ready-to-deploy software building block that can speed up product delivery.
